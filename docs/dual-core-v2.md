# 双核共振 v2.0：功能与上线边界

本模块用于量化研究、人工交易检查记录，不连接券商，不自动下单。规则来自用户提供的策略说明与每日执行卡 v2.0，全部参数仍为未回测假设。

## 页面

登录后访问 `/#/dual-core`。分阶段记录：09:30 数据检查、14:30 预警、14:45 终判、周五复核。执行卡含 Step0–11、情绪面板、指数阈值、累进降档、仓位预算、行业与个股过滤、持仓建议、人工成交记录、次日预案、复盘、审计和打印。

## 安全与数据边界

- 自动数据缺失、来源未核验、关键数据超过120秒、交易日历未核验时不授权开仓。
- 手工数字用于参考计算与记录，永远标记 manual/unverified；不能通过修改来源字段解锁实时开仓。
- 当前尚未接通满足全部关键源与120秒要求的可信实时采集器，因此线上自动判定仍可能显示 source_missing。日线历史不冒充14:45快照。
- 可信来源事件形成的逐用户当日冻结跨阶段、删除和重新建卡保留；客户端不能清除。
- 执行卡按登录用户、日期、阶段隔离，revision 防覆盖，更新及软删除留审计。
- 所有持仓操作均为未执行建议；T+1、跌停封死、未知可卖状态不视为已成交。
- 未完成回测前总仓上限不超过50%；不是收益承诺或买入建议。

## 文档冲突的显式处理

1. 以编号决策树顺序为准：清仓风险优先，Step5形态止盈先于Step6均线减仓；页面说明此口径，不隐藏矛盾。
2. 新开仓总仓上限减20个百分点，按字面计算。试错10%减20个百分点归零，提示冲突并阻断，不改算为乘以80%。
3. 档位、总仓、单票及持仓数同时约束取最严，不因候选选股失败忽略已有仓位合规减仓。

## 验证

后端包含规则阈值、优先级、容器校验、日历、冻结、租户隔离、revision和真实UI payload→TestClient→SQLite回读测试。前端包含Vue SFC挂载与DOM操作测试，不能把合成数据测试称为真实行情回测。

运行：

```sh
cd backend
python -m pytest tests -q
cd ../frontend
npm ci
npm run test:dual-core
npm run build
```

Docker部署仍须在前端构建后重建镜像并重建容器；仅 git pull 或重启旧镜像不会更新构建资源。数据库升级仅新增执行卡/审计/冻结表，部署前使用SQLite backup保存一致性备份。
